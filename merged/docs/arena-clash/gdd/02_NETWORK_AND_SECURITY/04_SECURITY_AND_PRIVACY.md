# Child-safety and security checklist

Anonymous guests, no email or open chat. Teacher sign-in authorizes host only. No location, public leaderboards, profile tracing, marketing identifiers, targeted ads, gambling, public friend discovery or student-to-student messaging. Minimum necessary player alias, per-match capabilities and short retention. Ensure moderation flows work and students cannot steal teams by changing WebSocket JSON. CSP allows only the correct worker origin, `fetch` uses HTTP(S) and sockets use WS(S). No `rejectUnauthorized:false` in prod Postgres TLS; configure provider-valid CA and hostname verification. Require ≥32-byte random shared secret consistently in Next control plane and worker, not just length 16. Allow only expected frontend origins, no wildcard in prod; secure `/metrics` from public scraping if it exposes room/seat metadata. Avoid leaking tokens through links/referrers, logs or query strings.

All five question types must prevent answer-key leaks to student/projector until reveal. Add adversarial tests for forged submission, hand-edited team ID, spectator host actions, cross-room token, duplicate action, speed hack, replay answer, huge packets, forced expired token.
